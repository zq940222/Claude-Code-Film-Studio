# 引擎降级链显式化，且视频生成不设备选

各能力（设定图 / 视频 / 配乐 / 精剪 / 发布）的主用引擎与降级路径此前散在各 agent 规范里，
写法互不统一——art-director 有完整的"判定不可用 → 降级 → 告知"，composer 只写了"停下报告"，
**operator 完全没有降级路径**（半自动发布挂了会怎样，规范没说）。我们决定把降级链收成
工作区 CLAUDE.md 里的**一张单一真源的表**（主用 → 备用 → 兜底），配三条硬规则，
并在 `project.json` 增加可选 `providers` 块让用户固化偏好。

同时明确一条**反向决定**：**视频生成不设备选引擎。即梦不可用时停下，不换引擎。**

## Considered Options

- **维持现状（降级逻辑各 agent 自己写）**：改动为零，但已经产生了实际缺口（operator 无降级路径），
  且"静默降级"无人约束——用户可能拿到降级路径的产物却以为是主用质量 — 拒绝
- **引入 OpenMontage 式的 tool_registry + selector 多 provider 自动路由**：能力最强，但它建立在
  57+ Python 工具类、能力声明与依赖探测的基础设施上；film-studio 是 markdown 插件 bundle
  （零第三方依赖、跨平台、跨运行时），引入注册表等于重写整个插件形态 — 拒绝
- **给视频生成也接 1-2 个备选引擎**（如其他文生视频服务）：表面上提升可用性，实则破坏一致性根基（见下）— 拒绝
- **降级链写成一张表 + 三条硬规则 + 可选 providers 块（选定）**：零新增依赖、四种形态通用、
  各运行时都能读；代价是降级仍靠 agent 遵守规范执行，没有机制强制

## Consequences

- **视频这一路的 `fallback` 恒为空数组**。理由是本工作台的三个一致性支柱全部绑定在 Seedance 上：
  风格锁（STYLE LOCK 是按 Seedance 的提示词响应调的）、角色一致性（`multimodal2video` 的 @引用设定图）、
  原声音轨（即梦生成的视频自带台词与音效）。中途换引擎不是"换个供应商"，是**整片作废重做**——
  已生成的镜头与新引擎的镜头放在一条时间线上必然穿帮。因此宁可停下等，也不降级。
  **这是一条刻意不加能力的决定**，将来有人想"顺手接个备选视频引擎"时，请先回答如何解决上述三项
- **"无备选"必须显式写成空数组**，不能省略字段。空数组的语义是"主用不可用时停下告知用户"，
  与"没配置、走默认链"区分开——省略字段会被读成后者
- **静默降级被定为最不可接受的行为**。每次降级必须一句话告知：降到了什么、代价是什么
  （耗积分／画质／一致性／要手动）、怎么恢复主用。operator 的手动上传兜底另加一条：
  **绝不把未发布记成已发布**（`publish-log.md` 是发布事实的记录，不是意图的记录）
- **降级只由"主用不可用"触发**（未登录、被风控、页面改版、CLI 报错、依赖缺失、连续 2 次失败）。
  慢、麻烦、要多点几下都不构成理由——否则降级会变成 agent 图省事的默认路径
- **`providers` 块是可选的**，老项目没有该字段时按表里的默认链走，无需迁移；
  `project.schema.json` 对它做结构校验（每项 `{primary, fallback[], note}`），拼错的 provider 名会被
  `tools/validate_project.py` 抓出来
- **能力粒度而非 agent 粒度**：降级链按 image/video/music/nle/publish 五种能力组织，
  与"哪个 agent 在用"解耦。将来某个能力换主用引擎，只改表里一行，不必翻遍 agent 规范
