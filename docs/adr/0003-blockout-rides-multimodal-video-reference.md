# 白模走全能参考的视频参考位，且是可选阶段

即梦 Seedance 支持用 3D 白模（blockout）控制运镜与空间关系后，我们决定把白模能力实现为
**新增 `previz-artist` 白模师 agent + 可选的 `/previz` 阶段**，白模视频通过现有 `multimodal2video` 的
`--video` 参考位（≤3）进入生成管线——而不是等即梦官方 Blender 插件 / Seedance 2.5 的原生 3D 白模入口，
也不新造生成模式。因为 `dreamina` CLI 当前只暴露 seedance2.0 家族（720p、image≤9/video≤3/audio≤3），
2.5 的原生白模通路在 CLI 里还不存在；而"把灰白 3D 预演当视频参考让模型复刻机位轨迹"这条路今天就能跑通，
且**白模生产侧（Blender 脚本 + 白模师职责）与消费侧（哪个 CLI 模式吃它）天然解耦**，将来 CLI 暴露原生入口时
只需改摄影指导的模式路由与视频生成师的提交命令，白模生产完全复用。

## Considered Options

- **等 CLI 暴露 Seedance 2.5 原生 3D 白模 / 官方 Blender 插件再做**：语义最正，但时间不可控，且用户现在就有"运镜老是不照做"的痛 — 拒绝
- **凭空包一个 `blockout2video` 模式**：读起来整齐，但 CLI 没有这个命令，视频生成师会去提交不存在的子命令 — 拒绝
- **白模挂给美术指导（art-director）兼管**：少一个 agent，但 3D 场景搭建/相机动画与出图是两套技能，且美术已背着设定图+关键帧+水印清理 — 拒绝
- **白模做成强制阶段插在 `/storyboard` 之后**：流程整齐，但 Blender 是可选依赖、白模只对少数镜头有增益，强制化会阻塞不装 Blender 的用户 — 拒绝
- **新增 previz-artist + 可选 `/previz`，白模走 multimodal 视频参考位（选定）**：能力今天可用、职责清晰、跳过零成本；代价是多一个 agent 与一个可选外部依赖（Blender）

## Consequences

- **"精确运镜"与"1080p"互斥**：视频参考位只存在于 `multimodal2video`（封顶 720p），而 1080p 只在
  `image2video`/`frames2video` 的 3.5pro/3.0pro 上——有白模的镜头一律留在 720p multimodal，运镜优先
- **禁灰面句成为硬性提示词要求**：白模是灰白无材质的，不显式禁止就可能被复刻成"3D 渲染感"。
  因此白模提示词固定三句式（复刻句/分工句/禁灰面句），审片新增「白模复刻」检查项，
  回炉原因新增两类（"运镜没照白模走" / "白模灰面残留"），各有对应修订动作
- **一镜最多 3 段白模**（video≤3）。多节拍长镜"逐拍各一段白模、提示词按时间码点名 @videoN"的做法
  **尚未充分验证**，规范里要求首次使用先走门禁③的"先生成 1 镜校准"，不许直接铺开
- **目录非破坏性**：新增 `03-previz/` 与 `03-design/` 并列（`03-*` 视为"视觉预备"层），既有目录编号不动；
  `project.json` 增加可选 `status.previz`（取值多一个 `skipped`），仪表盘等外部工具需容忍该新增字段
- **Blender 成为可选外部依赖**：只有 `/previz` 用到，建项时探测但不阻塞；没装 Blender 的用户全流程其余部分零影响。
  白模脚本 `tools/blender_blockout.py` 仍守 CLAUDE.md 规则 3（Python stdlib + ffmpeg，跨平台，无第三方包；
  `bpy` 由 Blender 自带），并提供不需要 Blender 的 `--validate` 纯校验模式
- **门禁不变仍是四道**：白模本地渲染不耗即梦积分，`/previz` 只做轻确认（选镜清单）；但视频参考位按即梦规则
  可能加价，门禁③报价须把"含白模镜头数"单列，避免账单意外
- **升级路径明确**：待 CLI 暴露 seedance2.5（原生 3D 白模、50 路参考、30s 单镜、4K）后，改动点集中在
  摄影指导的能力矩阵/模式路由与视频生成师的提交命令；`blockout.json` 规格、Blender 脚本、白模师职责与
  审片检查项均可原样复用
