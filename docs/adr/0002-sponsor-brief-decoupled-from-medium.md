# 商单机制与创作形态解耦，广告不是形态

用户需要"像博主一样做风趣幽默无厘头视频、插入广告接推广变现"。我们决定拆成两个正交概念：**创意段子（`sketch`）**作为第四种创作形态（无厘头内容法则、独立条结构、固定人设），**商单（sponsor brief）**作为可选的创作输入挂在条上（每条 0..1 个，落 `01-script/ep{NN}-sponsor.md`）——而不是建一个"创意广告"形态把广告内建进法则。因为博主的真实经营节奏是"平时纯内容涨粉、接到单才恰饭"：广告是某一条的属性，不是账号的体质；绑进形态会让纯涨粉内容别扭，且其他形态（短剧/短片/动漫）将来接商单时机制无法复用。

## Considered Options

- **"创意广告"形态，植入内建为法则**：模型最简单，但每条默认带广告位，纯涨粉内容没有归属；且"广告"占了形态名，误导语义 — 拒绝
- **只做横切商单能力，不新增形态**：机制可复用，但"无厘头段子"的内容法则没有归属（短剧的黄金3秒/高反转 ≠ 段子的玩梗/反转包袱）— 拒绝
- **短剧形态的变体（format.variant）**：改动最小，但形态表出现"短剧≠短剧"的语义分裂，四处法则表都要加条件分支 — 拒绝
- **新形态 + 独立商单机制（选定）**：内容法则与变现机制各自归位；代价是两个概念、多一份 brief 文件

## Consequences

- 商单机制**形态无关**：门禁①的商单核对单（卖点覆盖/口播词逐字/禁忌零出现）与门禁④的合规检查（平台报备+广告声明）对所有形态生效；植入创作法则 v1 只在 sketch 编剧章详写，其他形态遇商单按通用原则处理
- 变现边界锁死在内容侧：接单/谈价/结算在星图/花火与线下，工作台不碰商务与财务数据
- 植入方式 v1 仅剧本级两式（神转折/明示口播），走现有生成管线零改动；中插硬广若未来要做，需动 editor/finalcut 拼接链路，属新决策
- `project.json` 增加可选 `sponsors` 摘要块（品牌名+状态），brief 文件是单一真源；仪表盘等外部工具若解析 project.json 需容忍该新增字段
