# /review 审片质检

## 运行时适配（跨 Agent 兼容）

- **支持 subagent 的运行时**（Claude Code / Hermes Agent 等）：按下文"调度 xxx agent"正常派发子代理执行
- **不支持 subagent 的运行时**（OpenClaw 等，以插件 bundle 方式安装）：正文提到"调度 X agent"时，
  改为读取插件根 `agents/<X>.md`（本技能目录上两级），以其为工作规范在当前上下文直接执行，效果等同
- **用户确认处**：有 AskUserQuestion 工具就用；没有则直接在对话中提问并等待用户回复，门禁语义不变


## 前置检查

- shotlist.json 存在且至少有 status=success 的镜头；否则先走 /shoot

## 流程（AI 初审 → 真人互动审片 → 提示词修订 → 回炉）

1. **AI 初审**：调度 **reviewer** agent 逐镜头抽帧审查，产出 `04-footage/ep{NN}/review-report.md`
2. 向用户呈现审片结论：通过 X 镜 / 建议回炉 Y 镜（附问题描述和抽帧截图路径，可 Read 展示关键帧）
3. **真人互动审片（默认进行，用户可跳过）**：用 AskUserQuestion 问用户要哪种审法——
   - **逐镜互动**：逐个给出镜头文件路径（`04-footage/ep{NN}/sh{NN}.mp4`，本地播放器打开；装了
     film-studio-dashboard 的可在"镜头"页逐镜播放），等用户看完用自然语言反馈：画面瑕疵、表演/情绪、
     节奏、切镜、与预期的差距……都收；用户答"过"即通过
   - **只看 AI 可疑镜**：只对 AI 标 ❌/⚠️ 的镜头互动，其余采纳 AI 结论
   - **跳过互动**：全部采纳 AI 结论
   收集到的反馈交 reviewer 合并进审片报告（逐条标 `[人工]`/`[AI]` 来源）。
   **人工判定优先于 AI**：人说回炉就回炉（即使 AI 判通过），人说放行就放行（即使 AI 判回炉）
4. **回炉确认**：用 AskUserQuestion 确认最终回炉清单 → reviewer 把回炉镜头在 shotlist.json 置回
   pending，并把合并后的问题清单结构化写入该镜头的 `rework_reasons`（见 reviewer 规范）
5. **提示词修订（反馈闭环的关键一步）**：有回炉镜头时调度 **cinematographer** agent——
   按每镜 `rework_reasons` 对照"反馈→提示词修订映射表"（见其规范）改写提示词，旧提示词存入
   `prompt_history` 可追溯；修订完把每镜"问题 → 提示词改了什么"呈现给用户过目（可再调整）
   - **运镜类回炉的升级路径**：回炉原因是「运镜执行差」「切镜没执行」「空间关系错」且**提示词已改过一轮仍不行**时，
     建议用户改走 `/previz` 给这几镜补白模（本地渲染、不耗积分、`--only sh{NN}` 单镜重渲），比继续改第三版文字有效得多
   - **已有白模的镜头**：区分两类原因分别处理——「白模灰面残留」补禁灰面句；「运镜没照白模走」先查白模画幅/时长是否与该镜一致，
     不一致回 `/previz` 重渲白模（免费），别拿错白模重生成
6. 提示走 `/shoot` 重生成（回炉同样过门禁③报价）；**瑕疵可接受、直接进成片**的分支则提示 `/finalcut`
7. 全部通过或用户放行后，告知下一步：**`/finalcut` 精剪成片**（推荐，非破坏性）；
   想先快速看节奏可选 `/edit` 出粗剪预览

## 注意

- 回炉是正常工作流，AI 生成一次全过的概率不高；但回炉烧积分，决定权永远在用户
- 互动审片的价值在"人看得出 AI 看不出的东西"（表演、情绪、节奏、观感），鼓励用户至少看回炉镜；
  但绝不强制——用户忙时"跳过互动"一样走得通
- 提示词修订只改"执行表达"，不擅自改分镜意图（景别/叙事变更属导演职责，需要时明确建议用户回 /storyboard）
